# W6.0 Test sandbox: verification

`KLM_CONFIG_DIR=<dir>` or `--config <dir>` (GUI and `klm-cli`) moves everything KLM keeps per user into `<dir>`:

| What | Where in the sandbox |
|---|---|
| `settings.json`, `parts.db`, `rates.json`, `thumbs/`, `pending-libs.json` (the pending queue), snapshot store path | `<dir>/` (all via `settings::app_dir()`) |
| KiCad's global tables (`kicad_env::config_dir`) | `<dir>/kicad/<newest version>/`; created with empty `sym-lib-table` / `fp-lib-table` (`10.0`) if missing, never the real one |
| `kicad-cli`'s own config (`kicad_common.json`, which it rewrites on every run, even `version`) | `KICAD_CONFIG_HOME=<dir>/kicad` is set on every `kicad-cli` process KLM starts |
| Preview cache | `<dir>/klm-previews` (else the OS temp dir, as before) |
| API keys | `<dir>/credentials.json`, **plain text**; the real Credential Manager is neither written nor read. `KLM_USE_REAL_KEYS=1` lets a key missing from the sandbox be read from the real Credential Manager (for live API checks). Writes always stay in the sandbox |
| "Is KiCad running?" | always false under a sandbox: its tables are not the running KiCad's, and a test must not be blocked by the user's KiCad |

Snapshots/history live inside each library (`.klm-history`), so they follow the library root from the sandbox's `settings.json`. There is no log file.

### Found while verifying

- `kicad-cli` rewrites `%APPDATA%\kicad\<ver>\kicad_common.json` on every invocation, including `version`. The first sandbox runs changed it, so KLM now sets `KICAD_CONFIG_HOME` for its `kicad-cli` processes under a sandbox (my own sandbox test's `kicad-cli version` probe had the same leak and was fixed). The final before/after diff (T5) is clean. A running KiCad also rewrites its own files, so a diff during a KiCad session is not proof of a leak; the check was done with no other KLM test touching the real config.
- Unchanged, outside the sandbox: the older tests (`cli_e2e`, `snapshot_e2e`, ...) pass `KLM_KICAD_CONFIG`/`KLM_SETTINGS` but not `KLM_CONFIG_DIR`, so their `kicad-cli` calls still touch the real `kicad_common.json`; the older `credentials` unit test uses the real Credential Manager (entry `klm-test-source`, deleted after). Both are listed in LIMITS.md.

### Not verified

- GUI interaction under the sandbox (clicking, saving settings) is W6.3's job; only start-up and shutdown were checked.
- `KLM_USE_REAL_KEYS=1` read path was not exercised (it would read real secrets); the code path is a fall-through to the existing `Entry::get_password`.
