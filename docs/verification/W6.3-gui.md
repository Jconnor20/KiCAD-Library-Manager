# W6.3 GUI test harness: verification

`cargo test -p klm-gui` renders the real `App` offscreen with `egui_kittest` (wgpu, no window on the desktop) and drives it through AccessKit names. Code: `crates/klm-gui/tests/gui/` (`harness.rs`, `screens.rs`, `bugs.rs`), pulled into the binary as a `#[cfg(test)]` child module so tests can reach `App` and its tabs (a 4-line change in `main.rs`, plus `pub(crate)` on `LibraryTab::attach_dialog` and `AttachDialog` in `library.rs`).

**Set-up per test:** a fresh tempdir used as `KLM_CONFIG_DIR` (the W6.0 sandbox), wiped and re-seeded each time: a global library of 3 parts (LM358 and RP2040 in ICs, RC0603FR-0710KL in Resistors, with different amounts of footprint/3D/datasheet), a project folder, 3 "imported" entries and 1 favourite in `parts.db`, a watched-downloads folder inside the sandbox, and all four distributor sources off. Tests run one at a time (shared sandbox). Search-tab tests put in a stub source that fails every call and counts them; the count stays 0. PNGs go to `target/ui-snapshots/<name>-<w>x<h>.png`, copies in `docs/verification/ui-snapshots/`.

A bug that is still open is a `#[should_panic(expected = "KNOWN BUG")]` test: it passes while the bug exists and fails ("did not panic") when it is fixed, which is the cue to remove the attribute.

## Seen in snapshots

- **All Library views:** every `✔` cell and sort arrow is an empty box; the Checks counts are the only readable status at a glance. Sim model is orange "missing" on all rows.
- **Library at 820x560:** the "Find missing datasheets" button wraps to a third row, pushing the table down; the Checks column is off the right edge (reachable only by scrolling sideways).
- **Library detail panel / context menu:** right-click selects the row and shows the same buttons in the panel; the panel is a thin strip at the bottom with a large empty area above it.
- **Edit dialog:** not modal (background stays live, not dimmed); the Datasheet field truncates the path; Apply is correctly disabled until something changes.
- **Preview:** works with real renders; thumbnails are about 140x105 so symbol text is small; the window sits at the top-left, covering the top bar, not near the row.
- **Alternatives:** same top-left placement; "For part" label after its dropdown; the window overlaps the Library controls.
- **Attach dialog:** the file name line shows an empty box after "x.pdf" (a glyph, probably an arrow).
- **Batch dialogs:** clear and readable ("This will change: ... add symbol LM358 in PRJ_ICs"), but not modal either.
- **Settings:** a popup with a heading and no Close button; key boxes are 40 px, the 👁 button is a box; the content scrolls to about 1300 px.
- **History:** "Version: Auto 2026-11-03" runs into the change text; three buttons per row, Delete next to Roll back.
- **Import:** a lone check box labelled "files" (its first word is missing) beside Import ZIP; otherwise fine.
- **Clean up, BOM:** mostly empty until a scan or read; BOM's Region box says "default".
- **Search with a source:** header fine at both sizes; column headers show `▯`; star buttons are boxes; right-hand lists are readable.

## Not verified

- Dialogs on Import, History, Clean up and BOM tabs, the "Close KiCad first" prompt, Search with results, display scaling other than 1x.
- Applying a batch, saving settings, importing: the tests open dialogs and read what they show; the only write exercised is Restyle (in the sandbox).
- The real sources are off, so nothing proves a real one is not called at GUI start-up; the stub proves the Search/Alternatives/Datasheet paths used here do not call.
