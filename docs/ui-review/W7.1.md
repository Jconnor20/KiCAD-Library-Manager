# W7.1 Settings as a sectioned popup: test plan and results

Code: `crates/klm-gui/src/tabs/settings.rs` (popup shell), `settings/pages.rs` (one fn per page), `standards.rs` (rules widgets only), `ui_kit::Section`, the `Msg::OpenSettings` arm in `main.rs`; tests in `crates/klm-gui/tests/gui/settings.rs`.
All checks run headless (egui_kittest, offscreen wgpu, sandboxed `KLM_CONFIG_DIR`); no window is opened on the desktop, the real `%APPDATA%` config is never read, and no source is called (Test results are injected as messages).
Snapshots: `docs/ui-review/W7.1/before/` (W7.0 branch, c1a503f) and `docs/ui-review/W7.1/after/`.

## Notes

- Standardise's Dry run / Apply (`standards::Standards`, with its worker thread) was removed from Settings; W7.3 adds it to the Library tab. The old code is in git (c1a503f, `crates/klm-gui/src/tabs/standards.rs`).
- Test buttons are not clicked by the tests (they would call a source); the result display is exercised by sending `Msg::Settings(Tested(..))`.
- The Settings popup is a resizable `egui::Window` over a click-blocking dim layer, not `egui::Modal` (Modal cannot be resized). Esc is consumed by the popup.
- `Section` has the 15 pages plus `General`, `Sources`, `Standards`, which open on the group's first page.
- Changing the library's location from the Libraries page moves it at once (as the top bar button does); Apply never overwrites `global_root` or `last_project`.
