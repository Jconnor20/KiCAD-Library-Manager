    Phase 1 · research

    How similar tools handle the same jobs

    Each card ends with what KLM should take from it.

    KiCad symbol & footprint choosers desktop

    • A filter box on top, a library tree on the left, and symbol and footprint previews stacked on the right.
    • Previews come first and metadata second.

    Take: KLM users live in KiCad all day. A right-hand inspector with the symbol above the footprint feels native without extra explanation.

    KiCad Plugin & Content Manager desktop

    • A list on the left and details on the right.
    • Install and remove actions queue into a "Pending changes" tray, then one Apply runs them.

    Take: This is the model for the Import queue and Clean-up fixes: stage, review, then Apply. KLM already applies through review dialogs, so a visible pending tray makes that explicit.

    Altium Components / Manufacturer Part Search desktop panel

    • One search engine drives both local libraries and supplier data, in the same view.
    • Model icons are green when the part is ready to place and grey when it isn't.

    Take: Search and Library should share one table component and one status-chip language (Sym · FP · 3D · DS). "In library" should be a state, not a separate badge style.

    Octopart web

    • Filters sit in a row across the top instead of a sidebar, explicitly to keep results usable in a narrow window beside CAD.
    • Price view and Specs view are two column sets over the same results.
    • Searches zoom into a suggested category.

    Take: Keep filters as a horizontal chip row. A view switch (Price ↔ Specs) suits Search and BOM.

    DigiKey / Mouser / LCSC web

    • Parametric tables are dense, with in-stock and RoHS toggles and a column chooser.
    • Prices show as quantity breaks.

    Take: Engineers accept high density in tables. Use mono numerals, right-aligned prices and a column chooser instead of truncating the description.

    SnapMagic / Ultra Librarian web

    • Part pages put symbol, footprint and 3D tabs above the fold, with download-by-EDA buttons.
    • Quality badges show verified or community.

    Take: In the inspector, previews are the hero. A small provenance line (LCSC · imported 3 Nov) answers "where did this come from?".

    Horizon EDA pool manager desktop

    • Tabs per object type (symbols, packages, parts).
    • When pools are stacked, each item gets a coloured box showing which pool it came from.

    Take: A thin colour marker separates global from project parts in one list, instead of a View toggle.

    InvenTree web, React/Mantine

    • Detail pages are built from panels (parameters, attachments, stock), each holding its own actions.
    • The community pushed for "usability over polish": load once, switch panels without reloading.

    Take: Put actions next to the thing they act on. Edit belongs on the fields panel and Attach on the files panel, not in a global toolbar.

    Zotero / Lightroom Library desktop

    • The classic library-manager shape: collections on the left, items in the centre, an inspector on the right.
    • Batch actions appear only when several items are selected.

    Take: Show selection actions (Copy to project, Export, Delete) in a contextual bar when rows are ticked, and hide them otherwise. That alone halves the Library toolbar.

    VS Code desktop

    • An activity rail, a status bar, and a Problems panel that opens on demand with a count in the status bar.
    • A command palette (Ctrl+Shift+P) for everything.

    Take: Replace the always-open log with a status bar showing a warning count; click it to open the log. Add a Ctrl+K omnibox: MPN search, jump to page, run an action.

    EasyKiConverter / jlc-cli direct competitors

    • EasyKiConverter is a Qt Quick desktop app with light and dark themes, batch conversion and BOM import.
    • jlc-cli and the JLC2KiCad tools are terminal UIs built for speed.

    Take: The bar is low. A coherent, KiCad-native look plus inline previews would set KLM apart.

    Constraint check: KLM is egui 0.37. Everything below can be built with egui::Style/Visuals (colours, corner radius, strokes, spacing), embedded fonts (FontDefinitions), SidePanel/TopBottomPanel layouts, and the existing ui_kit::table. Gradients, blur and animated transitions are off the table, and none of the options need them.
    Synthesis

    Design principles for the new KLM

    1 · Context, not paths

    Show the global library and project as a compact switcher in the title bar ("motor-ctrl ▾"). Full paths go in tooltips and Settings.

    2 · One status language

    Every page uses the same four chips: Sym · FP · 3D · DS. Solid means present, dashed amber means missing, red means broken, faded means optional.

    3 · Previews are the hero

    Selecting a part shows its symbol and footprint immediately, the way KiCad's own chooser does.

    4 · Actions live where they act

    Use one primary button per page. Selection actions appear when rows are ticked. Part actions sit in the inspector.

    5 · Stage, review, apply

    Imports, fixes and restyles queue into a visible tray with a count and are applied together, as in KiCad's PCM.

    6 · Quiet until needed

    The log collapses into the status bar, and empty pages explain what to do next.

    Phase 2 · styles & themes

    Four themes, in two light/dark pairs

    Every mock below uses the same layout (layout B, below) and the same parts so only the theme changes. They pair naturally: Bench + Datasheet is a neutral pair, and Board + Schematic is a KiCad-native pair taken from KiCad's own default editor colours. KLM already switches on dark_mode, so picking a pair gives both modes.

    Phase 3 · next

    What gets wireframed once you pick

    After you choose a theme pair and a layout, I'll wireframe each of these in that style as one clickable page you can comment on:

    1. Shell: title bar with project switcher, rail, status bar, log drawer, Ctrl+K palette
    2. Search: query, filter chips, Price/Specs views, results table, inspector with Import
    3. Import: drop zone and empty state, staged queue, conflict and category review, Apply
    4. Library: table, selection bar, inspector (previews, fields, files, alternatives), health filter
    5. BOM: project summary (cost, shortfalls, lead time), line table, swap-alternative flow
    6. History: snapshot timeline, "what changed" diff, restore
    7. Clean up: scan results grouped by problem, staged fixes, Apply
    8. Settings: as a full page with a section tree, instead of a modal
    9. Dialogs: Edit fields, Batch relink/copy, Delete review, Restyle preview, Standardise plan
    10. First run: choose library location, connect KiCad, add sources
